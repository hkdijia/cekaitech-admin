# cekaitech-admin MVP 设计

## 目标

`cekaitech-admin` 首版目标是先搭建可扩展的公司级后台框架，而不是立即实现完整业务闭环。第一版重点解决后台的布局、导航、应用/租户切换、页面扩展方式和后续 API 接入边界。

## 技术栈

- Vue 3
- Vite
- TypeScript
- Element Plus

选择该组合的原因是后台管理系统资料多，表格、表单、菜单、弹窗、分页、筛选等组件成熟，适合一个人 + AI 快速迭代。

## 首版范围

首版页面以“后台壳 + 占位页面”为主：

- 登录页占位
- 后台主布局
- 左侧菜单
- 顶部应用/租户切换
- 首页工作台
- 用户管理占位
- 用户限制/黑名单占位
- 律师认证审核占位
- 数据导入占位
- 系统设置占位

首版不接真实生产业务接口，不做生产级鉴权，不直连数据库。

## 信息架构

```text
登录页
  -> 后台主布局
      -> 首页工作台
      -> 用户管理
      -> 用户限制 / 黑名单
      -> 律师认证审核
      -> 数据导入
      -> 系统设置
```

顶部区域保留当前应用/租户切换入口。后续可以按小程序或业务线切换工作区，例如法律助手、聚会计分器、预约类小程序等。

左侧菜单承载功能模块。首版菜单可以使用本地静态配置，后续再由后端 API 返回菜单和权限。

## 数据与接口边界

`cekaitech-admin` 只通过 `miniapp-backend` 的受控 API 读写云端业务数据。

禁止边界：

- 不直接连接生产数据库。
- 不绕过 `miniapp-backend` 写业务表。
- 不直接操作各小程序本地缓存。
- 不直接控制本地 `crawler` 进程。

数据导入能力后续应走以下路径：

```text
local crawler
  -> local output files
  -> cekaitech-admin import page
  -> miniapp-backend controlled API
  -> cloud database
```

## 权限策略

首版只做登录占位和用户信息占位。生产级权限不在首版实现。

后续权限建议分阶段：

1. 静态登录占位，用于开发后台布局。
2. 接入 `miniapp-backend` 登录接口。
3. 接入菜单权限、按钮权限和操作审计。
4. 对敏感动作接入二次确认和审计日志。

## 页面说明

### 登录页占位

用于进入后台主布局。首版可以使用固定账号或 mock 登录态，不作为生产安全方案。

### 首页工作台

展示后台概览占位，例如待处理认证、用户增长、服务请求、数据导入任务状态。

### 用户管理

首版展示占位表格，后续接入用户查询、用户详情、状态筛选和应用维度过滤。

### 用户限制 / 黑名单

首版展示限制类型和状态占位。后续对接 `miniapp-backend` 的用户限制能力，用于封禁、限制登录、限制审核提交等场景。

### 律师认证审核

首版展示审核列表占位。后续支持查看材料、通过、驳回、记录审核意见。

### 数据导入

首版展示导入入口占位。后续用于上传本地 crawler 导出的结构化文件，并通过后端受控 API 入库。

### 系统设置

首版展示应用配置、菜单配置和运行参数占位。后续用于配置小程序工作区和后台菜单。

## 验证方式

设计文档阶段不运行自动化测试。

后续实现首版工程后，至少需要验证：

- `npm run build` 通过。
- 主要页面路由可访问。
- 菜单切换不报错。
- 移动到另一台机器后可按 README 安装依赖并启动。

## 暂不做

- 生产级登录鉴权。
- 后端真实接口对接。
- 复杂权限模型。
- 真实数据导入。
- 直接管理 crawler 进程。
- 直连数据库。
